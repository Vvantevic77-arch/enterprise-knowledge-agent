# 本地真实 HTTP 性能与容量

用户确认项目只在本机运行。本实验启动独立 Uvicorn 进程，通过 TCP HTTP 请求实际接口，使用隔离 SQLite；未接触现有用户数据库。环境与当前默认/Render 配置的 SQLite 检索路径相同，但不是线上服务器。

测量完成时间（UTC）：2026-10-12T07:22:55.087121+00:00。环境：macOS-15.6.1-arm64-arm-64bit、Python 3.12.14、8 个逻辑 CPU、1 个 Uvicorn worker；客户端与服务在同一电脑，SQLite 保存 1,536 维 JSON 向量，外部模型关闭。完整环境参数保存在原始 JSON。

## 方法与判定

每档 10.0 秒，至少 30 请求，重复 2 轮；最高通过档再各测 30.0 秒。预热 5 次完整问答。
低吞吐档会为满足最少请求数延长窗口；例如 10,000 条段落的单并发问答每轮实际约 112 秒。语料按文本哈希排序，分别取前 1,000 / 10,000 条；每个规模循环使用 100 个原始自然语言问题，问题的标注正例至少一条存在于当前语料中。

暂定容量标准：健康/知识库读取 p95≤1秒，离线 RAG 问答 p95≤2秒，每轮错误率≤1%。这只是本次明确设置的标准，未经业务方定义为正式 SLA。阶梯到首个失败档停止；边界介于通过档和失败档之间，没有测到边界则只给下界。

闭环并发表示同时发起且等待响应的请求数，零思考时间；客户端与服务在同一台电脑，包含 TCP、认证、数据库读取、问答检索、事务写入和引用读取。连接复用，超时15秒。每次问答使用唯一幂等键并检查 succeeded、非空答案、5条语料引用和非 replay。未验证答案事实准确率。

## 请求错误与服务日志

- 1,000 条段落，POST /v1/agent/runs，并发 2：{'HTTP 500': 2}，共 31 请求，错误率 6.45%。
- 1,000 条段落的服务日志出现 `sqlite3.OperationalError: database is locked`，并指向查询触发的 autoflush。日志同一异常可能出现多行，日志行数不能当作错误请求数；请求数取自上面的 HTTP 样本。

## 限制与瓶颈

- RAG 的 SQLite 路径每次读取全部 chunk 与 JSON 向量，重新构造 NumPy 矩阵，再在 Python 分词；缓存离线索引的21ms不能代表这个接口。
- `start_run` 在检索前写入 AgentRun/幂等记录，SQLite 写事务跨越整个检索，其他问答写事务等待同一写锁；加并发可能主要增加排队。
- `require` 对通过权限校验的 GET 也添加 AuditLog；后续查询触发 SQLAlchemy autoflush 写入，而 GET 结束没有 commit、会话关闭会回滚。因此认证读取也不是纯读路径，可能竞争 SQLite 写锁；这是代码路径分析，未在本次单独量化其占比。
- 单 Uvicorn worker 内的同步 embedding、矩阵构建和分词还会占用事件循环。知识库读取容量和健康检查容量都不能替代完整问答容量。
- 关闭了外部 embedding/LLM，缺少网络模型延迟、配额、Redis/Celery、反向代理、多worker、生产硬件和长期混合负载；这些边界不能当作线上最大并发用户数。
- 语料直接批量写入隔离数据库，复用生产切分和向量算法，计数来自数据库；未测上传和入库任务吞吐。
- 客户端与服务器共享资源；原始逐请求数据、HTTP/超时分布及服务RSS/CPU采样保存在 JSON，短窗口 p99 和低样本档仅作描述。
- 81,039 条的全库检索质量与缓存计算已另测，本报告 API 容量只适用于表中的实际入库规模，不能外推全库服务性能。

## 复现

```bash
.venv/bin/python -m evals.http_capacity --sizes 1000 10000 --levels 1 2 4 8 16 32 64 128 256 512 --seconds 10.0 --repeats 2 --min-requests 30 --soak-seconds 30.0 --timeout 15 --warmup-requests 5
```

结束后停止自己的测试进程并删除自己的临时数据库；原有应用数据保留。
